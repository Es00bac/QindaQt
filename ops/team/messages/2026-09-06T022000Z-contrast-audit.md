# Contrast audit — integrated icon/runtime surfaces

- Concrete P1 finding: `src/shell/desktop_controls/qml/SystemStatusApplet.qml:101` paints attention lane icons with `Tokens.status.warning.foreground`, and `src/shell/desktop_controls/qml/StatusLaneRow.qml`/other warning badges use the same role. `status.warning.foreground` is selected to contrast against the warning *background* (`#f2c66d` on dark themes -> near-black foreground; `#754800` on light themes -> near-white foreground), but these icons/text sit directly on transparent/raised panel surfaces. Approximate contrast is 1.59:1 (black on dark `#2c312e`) and 1.08:1 (white on light `#f7f6f2`), failing normal text/icon visibility. Use `Tokens.fg.default` (or an explicitly surface-contrasted warning role) for glyphs on ordinary surfaces; reserve warning.foreground for warning-colored backgrounds.
- Same concrete issue in `src/shell/task_list/applet/qml/TaskListEntryButton.qml:118` urgent `!`, `src/shell/task_list/applet/qml/TaskListApplet.qml:181` degraded icon, `src/controls/qml/ThemeCard.qml:124` preview-unavailable text, and `src/shell/desktop_controls/qml/ControlPopupFrame.qml:71` feedback text: all paint warning foreground on ordinary raised/transparent surfaces.
- `Tokens.accent.fg` uses examined pinned badge/button backgrounds (`accent.default`), so those paths are appropriately paired. Disabled/default shell icons use `Tokens.fg.disabled/default` consistently.
- Bounded checks for menu_handoff: render each listed surface under qinda-light, qinda-dark, qinda-dusk, qinda-macos, and qinda-high-contrast; compute contrast against the actual parent rectangle. Assert >=3:1 for icons/UI glyphs and >=4.5:1 for body text, including attention/degraded/preview-unavailable/feedback states. Also verify warning.foreground remains valid when text is placed on an actual warning background.
