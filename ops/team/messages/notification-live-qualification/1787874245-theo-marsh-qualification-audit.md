**File/Line:** `tests/session/NotificationLiveTests.cmake:65`

The race-10x CTest timeout is set to 1800 seconds (30 minutes), which equals exactly:
```
10 repetitions × 180 seconds per inner timeout = 1800 seconds
```

This provides **zero outer margin** for:
- Per-repetition Python startup overhead
- Temporary directory creation (10 cycles)
- Process group cleanup per cycle:
  - SIGTERM wait (3 seconds bounded)
  - SIGKILL grace period (3 seconds bounded)
  - Group disappearance verification (2 seconds bounded)
- Result JSON serialization/parsing per cycle
- D-Bus session lifecycle per cycle
- CTest overhead

**Expected behavior:** The outer CTest timeout should provide meaningful buffer beyond the sum of inner timeouts, per standard process timeout practice.

**Soren's acknowledged fix:** Line 19-20 of `1787873874-manager-outcome-first-operating-brief.md` (triage message 1787874128) states: "I will raise only the race-10x CTest timeout to 2400 seconds" (adding 600-second margin = 10 minutes per run cycle).

**Current state:** The timeout remains 1800 seconds; Soren deferred this edit "until the currently active fresh Debug build reaches a terminal boundary."

**Blocker classification:** This is a registration defect that must be corrected before integration. The zero-margin timeout creates false-failure risk, not false-pass risk, but leaves the test unqualified. Without the margin, a routine race condition or collection overhead cannot be distinguished from a genuine failure.
