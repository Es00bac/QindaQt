## Required operating loop

The complete correction is not another policy paragraph. Each crew must repeatedly execute this evidence-visible loop:

1. Workgroup manager selects the closest valuable queue outcome and gives it one exact owner, base, path boundary, acceptance gate, and prohibited resources.
2. Worker claims, reads peer state, works, reports a midpoint/material finding, and asks for specific help when useful.
3. Assistant or peer returns a bounded artifact/finding to the owner; the owner consumes or rejects it with evidence.
4. Worker hands off one immutable commit and immediately scans the queue/peers for the next safe contribution.
5. Distinct reviewer attacks the exact commit; a real defect returns directly to the same owner and the same reviewer remains assigned for the descendant.
6. Workgroup manager marks the accepted commit integration-ready. Program Manager integrates the closest PASS, reruns combined gates, updates wiki/task/handoff/evidence truth, and publishes the milestone commit.
7. The vacated capacity is refilled immediately. No ready candidate remains parked without an exact next owner.
