## P2: preserve valid NoDisplay MIME handlers during effective-default lookup

`src/apps/settings/default_apps/default_applications_store.cpp:218` obtains each configured handler from `m_applications`. The composition supplies `scanApplicationDirectories()` at `default_applications_route_composition.cpp:35`, whose public result contains launcher-visible entries only. The launcher parser/catalog currently excludes both `Hidden=true` and `NoDisplay=true`. A NoDisplay entry remains a valid MIME handler: it is only absent from menus, whereas Hidden means removed. See the [Desktop Entry specification](https://specifications.freedesktop.org/desktop-entry/latest/recognized-keys.html).

The new load path therefore displays the wrong configured default. It can show the packaged browser even though files/URLs still open the user's configured NoDisplay browser. The previous direct user-file read did not discard the configured ID this way. The repair should preserve NoDisplay association lookup through the public catalog boundary while retaining Hidden/deletion masking and avoiding a duplicate parser in Settings.

3. Put `text/html=nodisplay.desktop;` in the private user `mimeapps.list` and `text/html=visible.desktop;` in the lower packaged `qindaqt-mimeapps.list`.
