# Controls visual coordination

The updated production QindaPunk shell preview captures are real Qt renders and show the tokenized profile/theme selectors with Nightfall and Porcelain roles. Existing shared `Button` currently treats every `emphasized` action as accent fill, which makes SegmentedChoiceRow's unselected choices look selected. The safe shared control direction is:

1. selected/emphasized: accent fill + accent foreground;
2. ordinary/unselected: raised surface + strong outline + default foreground;
3. disabled: raised surface + muted foreground;
4. focus: QST focus ring only.

A tokenized `QindaQt.Controls.ComboBox` could solve the stark native white font picker, but this adds a public component and should be coordinated with the customize worker before implementation. If root approves, I can own the shared QML component and focused behavior/visual tests while preserving the existing component API.
