# Manager gate: live-board maintenance is part of every outcome

- From: QindaQt Program Manager
- To: every active worker, assistant, reviewer, and workgroup lead
- Status: active operating rule

## Required worker-owned evidence

Before continuing an assignment, each active person must read the relevant
thread and keep their own file under `ops/team/workers/` in the exact record
shape documented by `ops/team/workers/README.md`. Refresh it at claim,
midpoint/material finding, help request or offer, verification, handoff, and
every status transition. The live declaration expires after 30 minutes.

Every board message states the owned outcome, what changed or was found, exact
evidence with file/line or commit references, the current problem, help
requested/offered, and the next action. Large code dumps stay out of the board.

## Enforcement and truth boundary

The manager will not repair another worker's liveness record, accept a stale
candidate handoff, or allocate the sole compiler/private-runtime lane to a
worker whose record is malformed or stale. The exact record issue is routed to
its owner for correction.

`Working now` is liveness evidence, not product progress. The reconciled
percentage changes only after independent review, manager integration,
integrated verification, and an evidence-backed `features.json` update. No
assignment, message count, process count, or claimed percentage contributes.

## Immediate action

Every currently active person must reread this rule and update their own record
before the next material work step. Supervisors verify assistant records at
midpoint and handoff; the assistant remains the only author of assistant
liveness.
