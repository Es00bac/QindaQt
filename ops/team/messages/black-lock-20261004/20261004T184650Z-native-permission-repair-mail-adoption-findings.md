## Normal native prompt sequence for imported records

The normal QtKeychain primary read wins. Only EntryNotFound reaches the typed imported adapter (`imported_password_backend.cpp:27`). The bridge pins native/standard names to one unique owner, searches the exact imported Password key, and, for its one locked match, calls standard `Unlock([item])` then that owner/path's `Prompt("")` (`imported_password_reader.cpp:145,165`). If the item is already unlocked, no unlock prompt is needed.

The real helper is `qindaqt-keyring-prompt`: keyboard-exclusive authentication overlay, visible window title `Passwords & Keys`, `Unlock your keyring`, collection label and masked keyring password field, Cancel/Unlock with Enter/Escape (`src/services/keyring/prompt/Main.qml:10,42`; `process_prompt_provider.cpp:108`; `docs/wiki/architecture/authentication-overlay.md`). The password belongs to the imported encrypted collection, **not** the IMAP or Google account. No create/migrate/delete/relabel is required by this read path. Successful completion rechecks actual item lock state, authenticated exact attributes and uniqueness before typed decoding. Wrong password, cancelled/expired/missing/unavailable helper or changed owner fails closed; originals stay preserved. The bridge marks Denied/Failed/Unavailable honestly rather than silently falling back.

Startup autoSync schedules syncAll and starts eligible account runtimes independently (`mail_service.cpp:197`, `mail_service_sync.cpp:120`); there is no bridge read coalescing. Native Service.Unlock creates an owner-scoped prompt per request (`service_methods.cpp:50`), and the provider permits up to four active helpers (`process_prompt_provider.cpp:27`). **Three locked imported accounts can therefore create several initial prompt objects/overlays, including when they share one collection. Do not promise exactly one prompt.** ADR-0343 matching-password fan-out tries other locked persistent stores after successful authentication (`secret_service.cpp:101`), and a single multi-collection prompt waits before asking again (`prompts.cpp:122`). It does not deduplicate/cancel already-open sibling requests; `startPrompt` does not first retire a request whose collection another prompt has unlocked. KDF minimum gap is500ms and fan-out paced550ms. A stale wrong-password approval can attempt collection authentication again (`CollectionStore::unlock` first clears prior unlocked state); no automatic dismissal strategy is supplied by this Office change. This is a bounded source-derived concurrency caveat, not observed live behavior or an assigned product change.

Helper process has a30-second deadline, daemon owned prompt60 seconds, Office reader70 seconds (`process_prompt_provider.cpp:109`, `prompts.cpp:13`, `imported_password_reader.cpp:60`). Cancel/wrong password completes with refusal; a later ordinary sync may retry. This worker performs no retry, approval, unlock or secret read.
