Daemon-authenticated pipewire.sec.pid may be an additional diagnostic/proof cross-check, never a substitute for the actual own connection.

## Cohesive private send-admission registry

One private collaborator, proposed console_send_admission_p.h/.cpp, owns current/retiring module incarnation and pinned graph-node identities. Before each load, allocate a fresh bounded instance token and exact capture/playback role declarations; include those in this module's two properties. Token and full name identify expected objects but are not authentication. Admit only a unique expected role whose actual daemon client equals the admitted own connection and whose media class, exact name, instance token and global object serial agree. Bind that serial/object incarnation once. Duplicate role, wrong client, missing lineage, serial replacement or stale worker generation cannot reuse the admission.

Use the same exact admission for gain writes and mapper exclusion. Active records permit writes to their pinned playback node; do not call unrestricted findNodeByName and then write a foreign same-name node. A new send remains quiet until both identity and its gain/headroom setup are admitted. Public endpoint roles are never classified as internal send streams, even when owned by this connection. Other service plumbing remains under its existing behavior; this packet does not invent a blanket hidden-client rule.

Retirement needs explicit observation lifetime: stop gain writes as soon as a declaration/module retires. Keep only the already pinned old object incarnation as a non-writable retiring internal object while its removal is pending; never reacquire a new object from that record. Actual object removal, Core loss or generation change clears it. A replacement must have its own fresh module/role/serial admission. Bound retiring records and deny new creation if that bounded ownership state cannot be represented; no unbounded tombstones or prefix-based reacquisition. This detail is required because current deferred module destruction and WpObjectManager removal delivery need not occur in the same callback.

Update admission before building the public snapshot, then exclude only its exact internal stream objects before reading normalized volumes or applying public stream capacity. Keep actual nodes available to private routing/meter/processing. Public stream-to-device links still use retained endpoint handles. Internal send-only links must not consume the public user-stream observation budget; retain finite traversal bounds derived from existing maximum sends/roles and public limits, with malformed external graphs still bounded. No changes to Audio1 DTOs, public device/stream ranges or generic readVolume interpretation are proposed.

## Actual bounded headroom and quiet start gate

Each independent stage remains -60..+12dB; the largest declared amplitude is 10^(36/20), approximately63.095734. Desired per-channel values include pan attenuation and never exceed that derived finite bound. Keep ordinary mixer percentages cubic. Convert only admitted console send amplitudes with cbrt at the mixer setter.

Set channelmix.max-volume only on admitted send playback creation to the smallest suitable upward-rounded float representation covering that derived bound. [Actual audioconvert source](https://raw.githubusercontent.com/PipeWire/pipewire/1.6.8/spa/plugins/audioconvert/audioconvert.c) clamps channel/aggregate gains to its configured maximum; its default10 would clip this legitimate three-stage request. No hardware, master, public endpoint or unrelated stream maximum changes. Read actual Props/PropInfo and setter acceptance; measure low-amplitude float PCM at +36dB so the fixture demonstrates full headroom without sample clipping. An argument string or pure computed constant cannot qualify platform headroom.

Initial node.param.Props plus disabled owned-stream property restoration remain a candidate mechanism, not an established quiet-start solution. Prefer initial zero stereo channels and mute, then the intended stereo gain/unmute in one accepted submission after identity admission; every boolean refusal/missing node must remain quiet and have bounded owning retry/error truth. Verify the first PCM blocks while mixer lookup/application is deliberately delayed and while stored restore data attempts a loud value. Inspect actual initial Props and final gain readback, and check setter false paths. If the loopback/restore/Props path emits a pre-admission sample, this recipe is not accepted: repair the private creation boundary before proceeding. Root has explicitly required this experiment with real loopbacks, not a generated-argument assertion.
